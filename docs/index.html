Playbooks, end to end

One command takes you from an idea or a bug report to a merge-ready PR. It is interactive until the last gate and autonomous after it.

Best-in-class skills, composed

Proven third-party skills (Matt Pocock, Cloudflare, Anthropic and others) are vendored verbatim. Thin agentic wrappers add the work item, model routing, gates and loops.

Auditable and resumable

Every run lives in one work item folder with an append-only event log. Re-run with the slug and it picks up where it stopped.

Use

Pick a playbook, answer its questions, then let it run until the PR is merge-ready. You merge.

Show commands for

First 5 minutes

  1. Open a repo with a green build, then run: 
    /agentic-implement-feature light add a --version flag to the CLI
  2. Answer the start questions, asked in one exchange: the workspace (a new worktree feat/{slug}, recommended; the current branch; or another branch), and whether to copy untracked files such as .env into the worktree.
  3. Light mode reads the code and checks the feature really is small. It then asks every blocking question in one go and writes plan.md.
  4. From here the run is autonomous. It gives you the resume command once, then implements one commit per task with a green gate after each, runs the reviewers and loops until no blocker or major is left, pushes, opens a PR, watches CI and comments, and reports when the PR is merge-ready.
  5. You merge. The skill sees the merge, then cleans up the worktree and branches and archives the work item.

Watch it happen with tail -f on the event log, or read .agentic/work/{YYYYMMDD}-{slug}/.

Playbooks

Playbooks are user-invoked: the model never starts them on its own. In Codex, playbooks and agentic-configure set policy.allow_implicit_invocation: false.

  • agentic-implement-feature

    Building something new. Input can be text, a file, a ticket key, a URL or a slug. Add light for small, obvious features.

    /agentic-implement-feature add CSV export to reports

  • agentic-change-feature

    Changing existing behaviour. Spec and plan record current vs target behaviour.

    /agentic-change-feature light make session timeout 30 min
    • A thin alias of agentic-implement-feature with branch change.
    • In light mode its ACs show (was: …), and T1 pins any kept behaviour that tests don't cover yet.

  • agentic-debug

    Fixing a bug: diagnose first, then a regression test, then the fix.

    /agentic-debug PROJ-123
    • Start asks only about the workspace (fix/{slug}).
    • diagnosing-bugs runs interactively and produces diagnosis.md: symptom, repro, root cause (file:line), ruled-out hypotheses and seam.
    • T1 is a failing regression test, then one approval round. The autonomous tail follows, and the merge-ready report includes the root cause.

  • agentic-pr-review

    Reviewing a PR once, with no fixes. With no argument, it uses the current branch's PR.

    /agentic-pr-review 42
    • Output is a local reviews/pr-report.md or one posted PR review.
    • Verdict: any blocker requests changes; any major or needs-user finding comments; otherwise it approves.
    • Security findings go through the disclosure guard before anything is posted.

  • agentic-security-audit

    Running a whole-repo or path-scoped security audit that files issues, with no fixes.

    /agentic-security-audit src/api
    • Start asks for scope, profile (quick, standard or deep), output dir and destination: local, github:owner/repo, jira:KEY, linear:TEAM or other.
    • Publishing creates a parent issue plus one child per confirmed finding.
    • To fix, hand the parent to agentic-change-feature, which runs full mode with tickets.

  • agentic-configure

    Writing your config: models, reviewers, folders, profiles, limits. Optional: without a config, built-in defaults apply.

    /agentic-configure --project
    • Detects your harnesses and their models, then walks through reviewers, the model table, folders, profiles and limits.
    • Writes only what differs from the defaults, and only after a yes. Models go in global config, everything else in project config.

Light vs full mode

Best forAnything with design choicesSmall, obvious features

A feature counts as straightforward only if all of these hold: 5 blocking questions or fewer; no ADR-worthy decision; no data migration or public contract change; no new domain term; about 5 tasks or fewer.

If it isn't straightforward, light mode says why and offers full mode; it never switches silently. Saying no stops the run and prints the resume command.

What you're asked vs what runs alone

You're asked

  • Start: workspace, mode, tickets, untracked-file copy (only what you haven't already answered)
  • Grill questions (product, functional, tech), each with a recommended answer
  • Spec and plan approval (full mode)
  • Escalation gate: confirm, escalate or revisit each structural decision
  • Interrupts after the last gate: a limit hit, a design-level PR comment, an unfixable red tree, a new escalation, a PR closed unmerged

Runs autonomously

  • Context gathering by read-only subagents
  • implement: one subagent and one conventional commit per unit, with a green gate (build, lint, typecheck, tests) after each
  • review: every reviewer, dedupe, fix list, re-review
  • babysit-pr: push, open the PR, poll CI and comments, fix
  • cleanup after merge

Hard rules

  • It never merges
  • It force-pushes only after a yes
  • The implement baseline must be green before work starts

Resume

After a usage limit, a crash or a closed session, re-run the same playbook with the work item slug. This works from any harness on the same machine.

/agentic-implement-feature 20261101-csv-export

On resume, it:

  • resolves open escalations first (decided, override or stop);
  • asks you to confirm when another session still looks active;
  • reuses the recorded workspace and earlier answers;
  • finishes any unfinished fix list, and skips steps that are already done;
  • for a unit cut off mid-edit, asks whether to finish it or stash it, and never discards work.

An abrupt stop loses at most the units that were in flight. Work items live in the gitignored output folder and workspace paths are absolute, so resume works on the same machine only. Pass a slug to any flow skill to resume it.

A playbook, end to end

agentic-implement-feature, from start to cleanup. Everything up to the last gate is interactive; the tail is autonomous.

Grilling happens inside agentic-to-spec (product, functional) and agentic-to-plan (tech). Every answer is logged to decisions.md, tagged structural or minor. Every focus recommends the leanest complete option, and never cuts validation at trust boundaries, error handling that prevents data loss, security, accessibility, or anything you asked for.

Gates and escalations

After the grills in agentic-to-spec and agentic-to-plan, each structural decision goes through a gate, where it is:

Confirmed
Becomes an ADR with status Accepted.
Escalated
Becomes an ADR with status Proposed, or an RFC. The run waits with status awaiting_decision.
Revisited
Goes back to grilling.

Confirmed knowledge is promoted by agentic-use-knowledge, which commits it as docs: … into docs/ (configurable via knowledge.root): tech/principles.md, tech/adr/, tech/rfc/, product/, ubiquitous-language/, landing-zone/.

After the last gate, only these interrupt the run: a limit hit, a design-level PR comment, a red tree that can't be fixed, a new escalation, or the PR closed unmerged. A new escalation always stops the run; resuming settles it first. Contract: escalation.md.

Reviewers and loops

Implement
Work is split into units: the fix list first, then tickets, then plan tasks. Each unit gets one subagent following Matt Pocock's implement and one conventional commit. A green gate (build, lint, typecheck, tests) runs after each unit; a red unit is retried implement.retries times, then you're asked.
Review
One report-only subagent per reviewers entry runs on the branch diff and writes reviews/{n}-{name}.md. Findings are deduped into a fix list for agentic-implement, then every reviewer re-runs. Only blocker and major loop; minor and nit are reported only. At review.iterations you're asked: another round, accept, or stop.
Babysit
Pushes, opens the PR against base, polls CI and comments with backoff, and fixes through implement and review. Never merges. Uses gh or a Bitbucket/GitLab CLI or MCP.
Cleanup
Removes the worktree and the local and remote branches, fast-forwards the default branch, and archives the work item. Asks first if the PR was closed unmerged or work is unpushed.

Model routing

Every step resolves its own model and effort. Built-in defaults are capability classes, not model ids, so the thinking lands on the strongest model and the volume work on cheaper ones.

Step keyRunsBuilt-in default
grillyour sessionfrontier high
review.claude-security-review, review.super-review, review.agentic-review-access-controlsubagentfrontier high
review.agentic-review-secretssubagentfrontier medium
auditevery agent security-audit launchesfrontier high
implementone subagent per unit, including every review and babysit fixcode medium
reviewparent of review.<reviewer>code medium
ticketssubagentfast low
context.code, context.docs, context.runtimeread-only subagentas explore
frontier
The strongest reasoning model available.
code
A strong, balanced coding model.
fast
The cheapest fast model.

Two routing keys cover work outside the steps and pin cheap models per harness: chore (grep, read a diff, rename, one-line edit) and explore (every read-only exploration). grill runs in your own session, so its value is a recommendation; you get a warning if your session runs a different model.

Resolution

model and effort each resolve separately. The first hit wins:

  1. steps.{harness}.{key}
  2. steps.{harness}.{parent}: the key up to its first dot (review for review.ub-mode)
  3. The built-in default: the key's own row, otherwise its parent's
  4. The harness default

Configuration

Configuration is optional. Two files are read: .agentic.json in the project, which wins, and ~/.agentic/config.json globally. steps merges per harness and key, and limits per key; other keys replace. A file only needs to hold what differs from the defaults.

{
  "reviewers": ["code-review", "claude-security-review", "agentic-review-secrets"],
  "steps": {
    "claude": {
      "grill": { "model": "opus", "effort": "high" },
      "implement": { "model": "sonnet", "effort": "medium" }
    }
  },
  "limits": { "review.iterations": 3 }
}
