# super-review overrides

Follow `super-review` on the brief's diff with these overrides. Its links outside its folder (`../super-board/…`, `../super-qa/…`, `scripts/…`, `.claude/bin/…`, writing-standard.md, block-template.md, run.md, run-workflow.md) aren't vendored: never open or run them; this file replaces them.

- **Not a board worker**: skip the readiness preamble (skills-readiness.md), "Review Loop behavior", "super-board integration" (Merge protocol, Prefix discipline, rate-limit etiquette included) except Lifecycle steps 5 and 7 as remapped below: no card move, PR thread, PR comment, PR-body edit, `gh pr ready` or merge gate.
- **Scope**: the brief's committed range; working tree out of scope (no dirty-file stop in step 1). Never fix code, whoever authorizes it (step 4).
- **Builder's account**: the work item's `implementation.md`, commit messages; PR mode adds the description and comments of the brief's PR (author notes = claims, never findings or approval). Read after your own hypotheses (step 2).
- **Conventions**: step 2's list (`clock.now()`, `numeric(12,2)`, …) belongs to another app; check only what the brief's standards sources state. ADRs = standards sources, not `docs/adr/`.
- **Skills** ("Skill dependencies"): `mattpocock-skills:codebase-design` → `codebase-design`. `mattpocock-skills:code-review` → skip when `code-review` is in the brief's reviewer list; else `code-review`, fixed point = base. `ponytail:ponytail-review` not available → step 3's inline ladder; never load `ponytail`.
- **Test rerun** (Lifecycle step 5): the checks `implementation.md` records, else the project's checks (scripts, Makefile, CI). Red → blocker, class Verification miss. No runtime verification (runtime-verification.md): a performance criterion without evidence → Verification miss.
- **Adversarial mode**: `truth_gate` = `non-trivial`, `truth_threshold` = 70, brief verbatim with its slots filled by paths, never pasted content: `#<P>` = the brief's PR number else branch, ACs = the spec source paths, Diff = the brief's diff command, Builder's summary = `implementation.md` (PR mode: the PR URL). No nested subagents → Code-grounder then Historian inline. Below threshold → major needs-user finding: rule `truth-check <score>/100`, evidence = lowest-confidence sub-agent finding, needs-user = confirm or refute that claim. `insufficient_data` → unverified in the report, no finding.
- **Prior report** ("Review remembers"): the brief's previous review and fix list (statuses `fixed` / `disputed` / `skipped`); round 1 unchanged. Carried ids are finding-contract ids, not R-ids.
- **Routing** (step 4, "Deepening opportunities"): no owners or lanes; every fix goes through agentic-review's fix list. Severities per finding.md's `super-review` row; a deepening opportunity is never filed. Lifecycle step 7's Block case (destructive schema, contract, money, auth, live-DB migration) → a needs-user finding for the human call, split per finding.md when a code fix also applies. A clean diff that only touches those areas is not a finding.
- **Report** (step 6): "Output format" (writing-standard.md § 4) is replaced by the finding contract: verdict line per finding.md's Verdict, then its header and `✅ Done` evidence and unverified items as the report body, then `## Findings` with `rule` = class + violated AC or standard.
