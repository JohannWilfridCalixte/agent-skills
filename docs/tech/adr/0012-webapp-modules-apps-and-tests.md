# 0012 - Webapp modules, apps, design system and test seams

**Status:** Accepted
**Date:** 2026-11-03

## Context

control-tower organises code as module slices (ADR 0003) with a web SPA that depends only on wire contracts (ADR 0005). agentic reuses that logic at smaller scale.

## Decision

- Scope `@agentic/*`. Packages: `kernel-result` (copied), `domain-shared` (ports `ProjectRegistry`, `HistoryLog`, `CommandRunner`), `domain-{projects,history,config,install,vendoring,work-items}`, `contract-http` (one zod subpath per module), `adapter-cli-exec`, `design-system`, `tooling-eslint-config`.
- Each module owns a `domain-<x>` package, a server module, a contract subpath and a web route folder. Modules never import each other; cross-module needs go through `domain-shared` ports wired in the server composition root.
- Apps under `applications/`: `agentic` (TanStack Start SPA), `server` (Hono API), `cli` (`agentic` client commands over the API using `contract-http` only; `serve` starts the server).
- `design-system`: Tailwind 4 tokens with dark mode, shadcn components generated by the shadcn CLI (`components.json` inside the package), shared components (page-header, empty-state, callout, diff-viewer). The web app depends on it; it never imports contracts or domain.
- File access goes through ports: `ConfigStore` in `domain-config`, read-only `WorkItemSource` in `domain-work-items`. Filesystem implementations live in the server modules; in-memory fakes in each `testing.ts`. No separate fs adapter.
- Test seams, no Playwright e2e in v1: (1) Hono app in-process (`createTestApp` + `app.request()`) with in-memory repos and a fake `adapter-cli-exec`; (2) pure logic as unit tests in the domain packages; (3) web via vitest + testing-library with a stubbed api client; (4) CLI via injected fetch against `createTestApp`.
- One vitest check parses the `config.md` tables and fails when `domain-config` defaults diverge.

## Rationale

Same package logic as control-tower with boundaries enforced by lint and the manifest check; highest seam first keeps tests in-process and fast.

## Consequences

Six slices and eight packages for a small app: more boilerplate, clear ownership. No browser-level regression coverage.
